# ARKit 블렌드쉐이프 녹화/송출 프록시 (arkit-recorder) 설계

날짜: 2026-08-04
상태: 승인됨

## 1. 목적

아이폰 페이스 트래킹(iFacialMocap / FaceMotion3D, UDP 49983)을 녹화해뒀다가,
아이폰 없이도 Warudo에 가짜 트래킹 소스처럼 재생 송출하는 상시 실행 프록시 프로그램.
주 용도: 방송 중 자리비움 루프, 반복 연기 재생.

## 2. 확정된 사실 (Warudo 디컴파일 소스에서 검증)

- Warudo `iFacialMocapReceiverAsset`의 포트는 `[DataInput] public int Port = 49983`으로
  UI에서 변경 가능하며, 변경 시 리시버가 자동 재시작된다.
- Warudo 리시버는 순수 UDP 수신만 한다. 폰으로 보내는 핸드셰이크/시작 신호가 없다.
  따라서 어느 프로세스가 패킷을 보내든 동일하게 처리한다.
- 파서는 패킷에서 공백 제거 후 유일한 `=`를 기준으로 앞부분(블렌드쉐이프),
  뒷부분(head/eye)을 나눈다. `=`가 2개 이상이면 프레임 전체를 버린다.
- 블렌드쉐이프는 `이름-정수값|...` 형식이며 Warudo가 0.01을 곱한다 (0~100 → 0.0~1.0).
- head는 `head#pitch,yaw,roll,x,y,z`, 눈은 `leftEye#p,y,r` / `rightEye#p,y,r` (Euler 각).
- `trackingStatus`가 블렌드쉐이프 키로 들어오며, 값이 0이면 Warudo는 그 프레임을 무시한다.
- 수신 패킷이 0.5초 이상 없으면 Warudo는 트래킹 끊김으로 처리한다.

## 3. 아키텍처

```
[패스스루 / 녹화]
아이폰 앱 --UDP--> 녹화기 :49983 --원본 그대로--> Warudo :49984 (127.0.0.1)
                      |
                      +--> (녹화 중일 때) clips/이름.jsonl 기록

[재생]
clips/이름.jsonl --> 녹화기 --원래 타이밍대로--> Warudo :49984
                     (이 동안 라이브 패킷은 전달 차단)
```

- 스택: Python 3, 표준 라이브러리만 사용 (socket, threading, json, tkinter).
  외부 의존성 없음.
- 위치: `E:\Works\arkit-recorder\`
- 아이폰 앱 설정은 변경 불필요 (PC IP만 입력하는 구조이므로).
- 1회 설정: Warudo 씬의 iFacialMocap Receiver 포트를 49983 → 49984로 변경.

## 4. 동작 모드 (상태 머신)

| 상태 | 동작 |
|------|------|
| 패스스루 | 수신 패킷을 그대로 Warudo로 전달 |
| 녹화 중 | 패스스루 유지 + 타임스탬프와 함께 파일 기록 |
| 재생 중 | 라이브 패킷 전달 차단, 클립 패킷을 타이밍대로 송출 |

전이: 패스스루 ↔ 녹화 중(녹화 버튼), 패스스루 ↔ 재생 중(재생/정지 버튼, 클립 종료).
루프 체크 시 클립 끝에서 처음으로 되감아 반복.

## 5. 전환 블렌딩 (크로스페이드)

표정 점프를 막기 위해 다음 경계에서 파싱-보간-재직렬화로 크로스페이드한다.

- 라이브 → 재생 시작: 0.3초 (마지막 라이브 프레임 → 클립 첫 프레임)
- 재생 종료 → 라이브 복귀: 0.3초 (클립 마지막 프레임 → 현재 라이브 프레임)
- 루프 경계: 0.5초 (클립 끝 → 클립 처음)
- 지속 시간은 config.json에서 조정 가능.

보간 규칙:
- 블렌드쉐이프 정수값: 선형 보간 후 반올림
- head/eye Euler 각: 최단 경로(shortest-path) 각도 보간
- head 위치: 선형 보간
- 한쪽에만 있는 키는 보간 없이 해당 값 유지

## 6. 녹화 포맷

- 파일: `clips/<이름>.jsonl` (한 클립 = 한 파일)
- 한 줄: `{"t": <녹화 시작 기준 상대 ms, 정수>, "d": "<원본 패킷 문자열>"}`
- 원본 패킷을 무손실 저장하므로 재생 충실도 100%, 텍스트라 디버깅 용이
- 용량: 60fps 기준 분당 약 5MB (자리비움용 수 분 클립에 충분히 가벼움)
- `trackingStatus-0`인 프레임은 기록은 하되 재생 시 송출을 생략한다
  (Warudo가 어차피 무시하는 프레임이며, 값을 1로 조작해 보내면
  무의미한 표정 데이터가 적용될 위험이 있기 때문)

## 7. 재생 타이밍

- `time.perf_counter()` 기반 스케줄링, 누적 오차 보정 (sleep 후 다음 목표 시각 재계산)
- 재생 스레드는 GUI/수신 스레드와 분리

## 8. GUI (tkinter 단일 창)

- 상태부: 아이폰 수신 상태(Hz, 마지막 수신 경과 시간), Warudo 전달 대상, 현재 모드
- 녹화부: 녹화 시작/정지 버튼. 정지 시 이름 입력 후 저장
- 재생부: 클립 목록(clips/ 폴더 스캔), 재생/정지 버튼, 루프 체크박스
- 콘솔/로그 출력은 ASCII와 한글만 사용 (이모지 금지 — cp949 크래시 방지)

## 9. 설정 (config.json)

첫 실행 시 기본값으로 자동 생성. 항목:

```json
{
  "listen_port": 49983,
  "forward_host": "127.0.0.1",
  "forward_port": 49984,
  "clips_dir": "clips",
  "crossfade_live_ms": 300,
  "crossfade_loop_ms": 500
}
```

## 10. 에러 처리

- 49983 바인드 실패(다른 프로세스 점유): GUI 상태부에 원인과 함께 표시
- 아이폰 패킷 0.5초 이상 끊김: "수신 없음" 표시 (Warudo와 같은 기준)
- 재생 중 파일 손상 라인: 해당 라인 건너뛰고 로그 남김
- 파싱 불가 패킷: 패스스루는 그대로 전달(프록시는 내용에 관여하지 않음),
  녹화도 그대로 기록, 블렌딩만 생략

## 12. 테스트 전략

- 유닛: 프로토콜 파싱/직렬화 왕복 무손실, 보간 수치, 재생 타이밍 오차,
  trackingStatus-0 송출 생략
- E2E: 가짜 아이폰 송신기가 실제 캡처 샘플 패킷을 쏘고, 가짜 Warudo 수신기가
  패스스루/녹화/재생 각 모드의 출력을 검증
- 실기 검증(실제 아이폰 + Warudo)은 사용자가 진행

## 13. 비범위 (v1에서 제외)

- 시스템 트레이, 글로벌 핫키
